# Style Lane Routing

Use one primary visual direction. Style skills are optional helpers, not required package dependencies or authorities over the user's brief.

## Selection Rules

1. Preserve explicit brand, palette, gradient, typography, stack, and product constraints.
2. Describe the direction in plain visual/UX terms before considering a named external skill.
3. If a matching skill is available, it may refine the direction. If it is absent, continue with the local guidance in this skill.
4. Never state that an unavailable skill was read or used.
5. Do not activate multiple taste skills solely because the user says “premium” or “modern.”

## Optional Lanes

| Optional skill | Useful signal | Local fallback direction |
| --- | --- | --- |
| `design-taste-frontend` | Restrained, production-oriented product UI | Clear hierarchy, deliberate density, coherent tokens, useful states |
| `gpt-taste` | Motion-led editorial or experimental storytelling | Define choreography, reading continuity, reduced motion, and runtime limits |
| `high-end-visual-design` | Existing concept needs visual polish | Refine type, spacing, media, surfaces, and micro-interactions |
| `minimalist-ui` | Explicit minimal/editorial/workspace direction | Reduce elements while preserving hierarchy, affordance, and contrast |
| `industrial-brutalist-ui` | Explicit tactical/raw/mechanical direction | Use structural typography, visible systems, hard edges, and functional density |

Conventional landing-page structure is valid when content and conversion needs support it. Reject it only when it is an unsupported default that hides the actual product or contradicts the brief. Decorative gradients and other stylistic devices are similarly context-dependent, not universally forbidden.
